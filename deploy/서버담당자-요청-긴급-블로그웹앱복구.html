부탁드리는 것 명령 1줄

1

블로그 웹루트에서 최신본 받기

서버 셸 
cd /home/blog && git fetch origin deploy && git reset --hard origin/deploy

블로그 관리자 화면의 [프로그램 갱신] 버튼이 원래 하던 일과 같은 명령입니다. 그 버튼이 지금 죽어 있어 직접 실행이 필요합니다. 이번에 받는 내용에는 문제를 일으킨 설정을 되돌린 WEB-INF/web.xml 이 들어 있습니다. 이 파일이 바뀌면 Resin이 블로그 웹앱만 다시 배치합니다(Resin 재기동 불필요).

2

살아났는지 확인

서버 셸 · 기대값 401 / 401 / 200 
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: blog.malgnsoft.com' http://127.0.0.1:8080/api/stats
curl -s -o /dev/null -w '%{http_code}\n' https://blog.malgnsoft.com/api/stats
curl -s -o /dev/null -w '%{http_code}\n' https://blog.malgnsoft.com/lms/association-society-training-lms/

앞의 두 줄은 401이 정상입니다(비밀번호 없이 불렀으므로 "인증 필요" = 살아 있다는 뜻). 지금은 둘 다 404가 나옵니다. 세 번째 줄은 어제 작성한 새 글이며 200이면 반영 완료입니다.

먼저 systemctl restart resin 은 피해 주세요

확인해 보니 같은 Resin에서 www.malgnsoft.com 이 정상 서비스 중입니다 (/cloud/inquiry.jsp → 200, 세션 쿠키 발급). 전체 재기동은 회사 홈페이지까지 순단됩니다. 위 1번으로 해결되지 않을 때만, 트래픽이 적은 시간에 검토해 주시면 됩니다.

블로그의 /api/* 와 .jsp 요청에 Apache 기본 오류 페이지가 돌아옵니다. 프록시 대상이 죽은 것이라면 502·503이 나야 하므로, Resin이 이 호스트의 URL을 더 이상 자기 것으로 주장하지 않는 상태 — 즉 blog 웹앱이 배치 실패로 빠져 있는 것으로 판단했습니다. 회사 홈페이지가 같은 Resin에서 멀쩡한 점이 이 판단의 근거입니다.

추가된 서블릿은 실행 검증을 거치지 못한 JSP였습니다. 웹앱 기동 실패의 가장 유력한 원인으로 보고 그 선언을 제거한 web.xml을 이미 GitHub에 올려 두었습니다. 위 1번 명령이 그것을 받아옵니다.

1번으로 안 살아날 때
A

서버 셸 
sudo touch /home/blog/public_html/WEB-INF/web.xml

Resin이 이 파일의 변경을 감지해 blog 웹앱만 다시 배치합니다. 회사 홈페이지는 그대로입니다.

B

서버 셸 · 로그 경로는 설치에 따라 다름 
sudo systemctl status resin --no-pager
sudo grep -iE 'blog|web-app|exception|error' /var/log/resin/*.log | tail -60

blog.malgnsoft.com 웹앱의 배치 실패 사유가 여기 찍힙니다. 그 내용을 sales@malgnsoft.com 으로 보내주시면 저희 쪽에서 원인을 고쳐 다시 올리겠습니다.

마지막 수단

위 A·B로도 안 되면 sudo systemctl restart resin 입니다. 다만 회사 홈페이지가 함께 순단되므로 트래픽이 적은 시간에 부탁드립니다. 재기동 후 systemctl is-enabled resin 으로 부팅 자동기동 여부도 확인해 주시면 좋겠습니다.

배경 — 이 블로그는 이렇게 배포됩니다

글의 원본은 서버가 아니라 GitHub에 있습니다. 글을 쓰면 GitHub에서 완성된 정적 페이지가 만들어져 deploy 브랜치에 쌓이고, 서버는 그것을 git reset --hard 로 받아가 /home/blog/public_html 에 펼칩니다. 그래서 서버 안에서 파일을 고치면 다음 갱신 때 사라집니다 — 수정은 항상 GitHub 쪽에서 합니다.

받아오라고 지시하는 통로가 POST /api/update(관리자 화면의 [프로그램 갱신] 버튼)인데, 지금은 그 통로가 죽어 있습니다. 저희가 GitHub에 고쳐 올려도 서버로 내려보낼 방법이 없어 이렇게 한 줄 실행을 부탁드리게 됐습니다. 한 번 살아나면 이후로는 버튼으로 처리됩니다.
