무엇을, 왜 쉬운 설명

블로그 글의 원본은 서버가 아니라 GitHub에 있습니다

서버는 원본을 보관하지 않습니다. GitHub이라는 원본 창고에서 완성된 페이지를 받아다 보여주는 역할만 합니다. 지금까지는 받아오기만 했고, 창고가 공개라 열쇠가 필요 없었습니다.

이번에 관리자 화면에 글쓰기 기능이 붙었습니다. 글을 저장하면 그 원본 창고에 글을 넣어야 합니다. 넣으려면 쓰기 열쇠가 필요합니다. 그 열쇠가 GitHub 토큰이고, 서버가 읽을 수 있는 자리에 파일로 놓아주시면 됩니다.

왜 서버에 바로 저장하지 않나요?

서버는 갱신할 때마다 자기 내용을 창고 것으로 통째로 덮어씁니다(git reset --hard). 서버에 직접 쓴 글은 다음 갱신 때 사라집니다. 그래서 창고에 먼저 넣고, 서버가 그걸 받아오는 순서여야 합니다.

역할이 둘로 나뉩니다

블로그 담당자 GitHub에서 토큰 발급 저장소 소유자만 할 수 있습니다. 발급한 값을 서버 담당자에게 안전한 방법으로 전달합니다.
서버 담당자 전달받은 값을 파일로 저장 명령 3줄이면 끝납니다. 재기동도, 설정 변경도 필요 없습니다.

① 토큰 발급 블로그 담당자

GitHub에 로그인한 뒤 아래 순서로 들어갑니다.

Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token

항목지정할 값
Repository accessOnly select repositories → freerahn6/malgnblog
Repository permissionsContents: Read and write — 나머지는 전부 No access
Expiration만료일 지정. 만료 전에 새로 발급해야 글 저장이 멈추지 않습니다

발급 직후 화면에 한 번만 보이는 값을 복사해 두세요. 창을 닫으면 다시 볼 수 없습니다.

② 서버에 놓기 서버 담당자

1

토큰을 파일로 저장

아래를 붙여넣으면 값을 물어봅니다. 화면에 찍히지 않고 명령 기록에도 남지 않습니다.

서버 셸 
sudo -u blog bash -c 'read -rsp "GitHub 토큰: " T && printf "%s\n" "$T" > /home/blog/data/github.token'
sudo chmod 600 /home/blog/data/github.token
sudo chown blog:blog /home/blog/data/github.token

chown 의 소유자는 Resin을 실행하는 계정이어야 합니다. Resin을 blog 가 아닌 계정으로 돌리고 계시면 그 계정 이름으로 바꿔주세요.

2

제대로 놓였는지 보기

서버 셸 
ls -l /home/blog/data/github.token

-rw------- 로 시작하고 소유자가 Resin 실행 계정이면 정상입니다.

3

실제로 통하는지 확인

관리자 비밀번호가 있어야 확인됩니다. 비밀번호를 먼저 검사하기 때문에, 비번 없이 부르면 토큰이 있든 없든 늘 unauthorized 가 납니다(토큰이 있는지를 바깥에 알리지 않기 위해서입니다).

서버 셸 
# 비밀번호는 /home/blog/data/admin.pw 의 값입니다
read -rsp '관리자 비밀번호: ' PW && echo
curl -s -X POST 'https://blog.malgnsoft.com/api/stats?write=1' \
     -d "pw=$PW" -d 'action=get' -d 'file=what-is-lms.md' | head -c 200; echo
unset PW
나온 값뜻
{"ok":true,"file":…,"content":"---\ntitle:… 정상. 토큰이 잘 놓였고 GitHub까지 통했습니다
{"error":"no_token"} 파일이 없거나 Resin 계정이 못 읽습니다 → 1단계의 경로·권한·소유자를 다시 확인
{"error":"unauthorized"} 비밀번호가 틀렸습니다. 토큰 문제가 아닙니다
{"error":"github_unavailable"} 토큰은 읽혔으나 GitHub 호출이 실패. detail 값과 Resin 로그를 알려주세요
{"error":"write_disabled"} web.xml 의 writeEnabled 가 false 입니다

함께 부탁드립니다 보안

관리자 비밀번호가 아직 gamma 라면 이번에 꼭 바꿔주세요

기본값 gamma 는 공개 저장소의 설정 파일에 적혀 있어 사실상 공개된 값입니다. 지금까지 그 비밀번호로 열리는 것은 조회수 통계뿐이었지만, 이제는 그 비밀번호로 블로그 글을 쓰고 고칠 수 있습니다. 성격이 달라졌습니다.

서버 셸 
sudo -u blog tee /home/blog/data/admin.pw <<< '길고-추측-불가능한-비밀번호'
sudo chmod 600 /home/blog/data/admin.pw

관리자 화면 주소와는 다른 값으로 정해주세요. 주소가 곧 비밀번호면 의미가 없습니다. 바꾸신 뒤 블로그 담당자에게 새 값을 전달해 주시면 됩니다.

미리 답해 두는 질문

이 토큰으로 무엇까지 할 수 있나요? 서버가 위험해지나요?

서버에 대한 권한은 전혀 없습니다. 이 토큰은 GitHub의 블로그 저장소 한 곳에서 파일을 읽고 쓸 수 있을 뿐입니다. 계정 전체나 다른 저장소에는 닿지 않습니다(Fine-grained 토큰으로 대상 저장소와 권한을 못 박아 발급합니다).

최악의 경우에도 피해는 블로그 글이 변조되는 것이고, 모든 변경이 GitHub에 커밋 기록으로 남아 되돌릴 수 있습니다.

토큰 값이 밖으로 새지 않나요?

브라우저로는 절대 나가지 않습니다. 서버의 JSP가 파일에서 직접 읽어 GitHub에 보낼 뿐이고, 화면·응답·로그 어디에도 값을 찍지 않습니다.

파일은 웹루트(public_html) 바깥인 /home/blog/data 에 두므로 웹으로 요청해도 접근되지 않고, 0600 이라 다른 계정도 읽지 못합니다.

서버가 바깥으로 통신하게 되는 건가요?

네, 다만 글을 저장할 때만 api.github.com:443 으로 나가는 아웃바운드 HTTPS 한 건입니다. 이미 사이트 갱신 때 github.com:443 으로 나가고 있어 통신 상대가 새로 늘지는 않습니다.

인바운드 포트는 그대로 80/443뿐이고, 새로 여는 포트는 없습니다.

안 하면 어떻게 되나요?

사이트·조회수·[프로그램 갱신] 버튼은 지금과 똑같이 동작합니다. 관리자 화면에서 글을 저장할 때만 "토큰 없음"으로 막힙니다. 급하지 않으시면 나중에 하셔도 됩니다.

나중에 끄고 싶으면요?

토큰 파일을 지우면 즉시 막힙니다. 기능 자체를 잠그려면 public_html/WEB-INF/web.xml 의 writeEnabled 를 false 로 두시면 됩니다.

참고로 누가 언제 무엇을 저장했는지는 /home/blog/data/admin.log 에 한 줄씩 쌓입니다.

재기동이 필요한가요? 서비스가 끊기나요?

둘 다 아닙니다. 파일을 놓기만 하면 다음 요청부터 바로 반영됩니다. Apache·Resin 재기동도, 설정 변경도 필요 없습니다.

잘 안 될 때

증상확인할 것
no_token 이 계속 나옴 파일 경로가 /home/blog/data/github.token 인지, 소유자가 Resin 실행 계정인지. 값 뒤에 빈 줄이 아니라 진짜 토큰이 들어갔는지(wc -c 로 길이 확인)
github_unavailable · TLS/SSL 오류 Resin이 쓰는 JDK가 낡아 GitHub의 TLS 1.2를 못 맞추는 경우입니다. java -version 결과를 알려주시면 대응하겠습니다
github_unavailable · 401·403 토큰이 만료됐거나 권한이 Contents: Read and write 가 아닙니다. 재발급이 필요합니다
확인 명령이 응답 없음 Apache의 /api/ 프록시와 Resin 기동 상태. curl -sI https://blog.malgnsoft.com/ 가 200인지 먼저 확인
참고 — 이미 끝난 설치 내용과 서버에서 도는 것들

아래는 이번에 하실 일이 아니라 현재 상태의 기록입니다. 전체 원문은 저장소의 deploy/서버담당자-설치가이드.md 에 있습니다.
