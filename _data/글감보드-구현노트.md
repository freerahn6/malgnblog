### 서버 API (전부 `/api/stats` 에 얹음 — 새 엔드포인트는 Apache 404)

| 요청 | 하는 일 | 응답 |
|---|---|---|
| `GET /api/stats?topics=1&pw=…` | 카탈로그에서 **삭제분을 뺀** 목록 | `{ok,catalog,generated,count,trashCount,topics[],trash[],orphan[],date}` |
| `POST /api/stats?topics=del` 본문 `pw=…&id=…` | 삭제 기록에 id 추가(**멱등**) | `{ok,id,deleted:true,changed,count}` |
| `POST /api/stats?topics=undel` 본문 `pw=…&id=…` | 삭제 기록에서 제거(복구, **멱등**) | `{ok,id,deleted:false,changed,count}` |

- 비번 틀리면 **401**, del/undel 을 GET 으로 부르면 **405**, id 가 비었거나 64자 초과면 **400**, 저장 실패면 **500**.
- 목록은 GET+쿼리 비번(기존 `/gamma` 와 동일, Apache 가 `blog_noquery` 로그포맷), **쓰기는 POST 본문 비번**(기존 규약 F4).

### 설계 결정 4가지와 이유

1. **삭제 기록은 "id 목록"만 웹루트 밖에 둔다.** 카탈로그(무엇이 있나)는 빌드 산출물, 삭제(무엇을 뺄까)는 서버 상태 — 둘을 섞지 않았다. `git reset --hard` 가 웹루트만 갈아엎으므로 이 분리가 곧 "영구 저장"의 구현이다. *(카탈로그 파일에 직접 표시하는 안을 버린 이유: 다음 배포에 통째로 덮인다.)*
2. **파일은 append 가 아니라 통째 재작성 + 원자적 교체**(`createTempFile` → `Files.move`, 실패 시 `renameTo`). JSON 배열은 닫는 괄호 때문에 진짜 append 가 불가능하고, 이 방식은 `stats-store.jspf` 의 `save()` 와 같은 관용구라 중간에 죽어도 파일이 깨지지 않는다. 읽기~쓰기 전체를 **애플리케이션 스코프 잠금 객체**로 감싸 연타 삭제에서 마지막 한 건만 남는 일을 막았다. *(static 잠금을 버린 이유: 정적 include 라 JSP 마다 클래스가 갈려 공유되지 않는다. `ctx` 자체를 잠그는 안을 버린 이유: 조회수 수집 경로가 `store(ctx)` 에서 같은 잠금을 쓴다.)*
3. **서버가 카탈로그 원소를 "원문 조각 그대로" 잘라 되돌린다.** 값을 다시 조립하지 않으므로 이스케이프·유니코드가 변형될 여지가 없다. 이를 위해 JSON **스캐너 4함수**(`jsWs`/`jsString`/`jsValue`/`jsArray`)만 손으로 짰다. *(완전 파서를 쓰는 안, 외부 라이브러리를 넣는 안 둘 다 버렸다 — 전자는 JDK 없이 검증 불가한 코드량이고 후자는 금지.)*
4. **목록을 HTML 에 굽지 않는다.** `/new` 는 공개 URL 이라 view-source 로 파이프라인이 통째로 노출된다. 비번 확인을 통과한 API 응답으로만 그리고, 카탈로그는 `WEB-INF` 아래(웹 직접 접근 차단)에 둔다. 비번은 `sessionStorage['bpw']`(= `/gamma` 와 같은 키, 브라우저 닫으면 소멸).
5. **삭제는 확인 1회 + 그 행만 제거 + 7초 실행취소 토스트**, 그리고 **휴지통**(복구 버튼)까지 둔다. 마스터가 실수로 지울 수 있다는 전제 때문에 되돌릴 길을 두 겹으로 뒀다.

### 알아둘 것

- **카탈로그에서 글감이 사라져도 삭제 기록은 남는다**(id 기준). b1 이 같은 id 를 다시 넣으면 **계속 숨겨진 채로 나온다** — 의도한 동작("내가 삭제할 때까지 영구")이다. 그런 기록은 응답 `orphan[]` 으로 따로 내려가고 화면 휴지통에 "카탈로그에 없는 기록"으로 보인다.
- **`_data/topics.json` 에 `id` 가 없거나 64자를 넘으면** 빌드가 제목 해시로 대체 id 를 만들고 `[경고]` 를 찍는다. 이때는 **제목이 바뀌면 삭제 기록이 풀린다** — b1 에게 id 를 명시해 달라고 할 것(현재 94건 전부 id 있음, 최대 41자).
- 카탈로그를 못 읽어도 **빌드는 멈추지 않는다**(곁다리 화면 하나 때문에 블로그 배포 전체를 막지 않는다). 대신 `/new` 가 "카탈로그가 없습니다"를 화면에 그대로 말한다.
- `/new` 와 기존 카테고리 `/news/` 는 한 글자 차이다. 마스터가 오타를 내면 뉴스 카테고리 페이지가 열린다(동작상 문제는 아님).
- CI 건전성 검사(`deploy.yml`)에 `topics.json` 존재 검사는 **넣지 않았다** — 카탈로그가 없어도 사이트는 정상이므로 배포를 막을 이유가 없다. 넣고 싶으면 `WEB-INF/web.xml` 검사 옆에 한 줄 추가하면 된다.
