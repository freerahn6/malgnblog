## 1. 목표 · 범위 · 비범위

### 1.1 목표
현재 `/gamma` 단일 통계 대시보드를, 운영자가 **글을 직접 보고·켜고끄고·고치고·지울 수 있는 실용 백오피스**로 고도화한다. 정적 생성 + git SSOT 모델을 깨지 않고, 기존 배포 파이프라인(Actions→deploy→`/api/update`)을 재사용한다.

### 1.2 범위 (In scope)
- 관리자 콘솔 3영역 분리: **대시보드 / 통계 / 글관리** + 로그인.
- 글관리: 목록·검색·필터·정렬, 행 액션(**수정 · 삭제 · 온오프 토글**), 편집 화면(WYSIWYG 본문 + 메타 폼).
- 콘텐츠 쓰기 경로 확정(GitHub API 커밋) 및 기존 빌드/배포 정합.
- 신규 JSP API 계약(목록·조회·저장·상태변경·삭제·이미지).
- 보안 최소 보강(비번 전달 방식·감사로그·토큰 분리).

### 1.3 비범위 (Out of scope) — 명시적으로 안 한다
- 다중 사용자 계정/실명 로그인/SSO 연동 (단일 관리자 유지, 단 역할 축은 미래 확장 여지만 정의).
- 실시간 협업 편집, 예약 발행, 워크플로우 승인.
- 방문자 유니크/세션/체류시간/유입경로 등 **track.jsp가 지금 수집하지 않는 지표**(추가 수집 필요 — 로드맵에만 언급).
- DB 신설. (아래 3장 결론: **DB 불필요**.)
- 댓글·회원·검색엔진 색인 관리 UI.

### 2.3 공통 세션·인증 흐름
- 로그인 시 `/api/auth`가 **불투명 세션토큰**(랜덤 32B)을 발급, `Secure; HttpOnly`가 불가한 JSP-only 환경이면 **sessionStorage 저장 + 이후 요청은 `Authorization: Bearer <token>` 헤더**로 보낸다(쿼리스트링 금지, F4 보강).
- 세션 만료(가정: 30분, web.xml `session-timeout`과 정합) 시 모든 API가 401 → 자동으로 로그인 게이트 복귀.

## 3. 콘텐츠 모델 재설계 (핵심 난제 정면 돌파)

### 3.1 문제 정의
콘텐츠 SSOT는 `articles/*.md`(git). 웹 관리자에서 WYSIWYG로 수정·삭제·온오프하려면 "편집 결과가 어디로 흘러가는가"를 확정해야 한다. F2에 의해 **서버 로컬 쓰기는 배제**되므로, 후보는 실질적으로 다음과 같다.

### 3.2 A / B / C 트레이드오프

| 항목 | (A) GitHub API 커밋 왕복 | (B) 동적 오버레이 | (C) 하이브리드(오프·삭제=동적 플래그, 본문=A) |
|---|---|---|---|
| 쓰기 위치 | 원격 `main`에 GitHub Contents API로 커밋 → Actions 재빌드 → deploy → `/api/update` pull | 정적 산출물은 그대로, JSP가 `/home/blog/data`에 오버라이드(편집본·숨김목록) 저장, 서빙 시 덮어씀 | 오프/삭제는 `data`의 플래그, 본문수정은 A |
| SSOT | **git 단일** | **정적+동적 이중** | 이중(상태는 동적, 본문은 git) |
| 온오프 즉시성 | 커밋+빌드 ~1~3분 | 즉시(다음 요청부터) | 즉시 |
| 본문수정 반영 | ~1~3분 | 즉시 | ~1~3분 |
| 서버 권한 | 원격 토큰만(로컬 push 불필요) | 로컬 data 쓰기(이미 stats.tsv로 검증됨) | 둘 다 |
| 서빙 계층 변경 | **불필요**(정적 그대로) | **필요** — 현재 Apache/Resin이 정적 HTML을 직접 서빙. 오버레이하려면 글 요청을 가로채는 JSP 필터/서블릿을 신설해 모든 article URL을 동적 경유시켜야 함(대공사, 성능·캐시 영향) | 오프/삭제만 필터 필요 |
| git 이력 | 깔끔(모든 변경이 커밋) | 없음(오버라이드는 이력 밖) | 본문만 이력 |
| `git reset --hard`(F2) 충돌 | 없음(원격이 진실, 서버는 늘 pull) | **위험** — data는 git 밖이라 살아남지만, 정적본과 오버라이드가 어긋나면 진실이 갈림 | 부분 위험 |
| 복구성 | git revert/history | 수동 | 혼합 |
| 구현난도 | 중(토큰·API·낙관적동시성) | 상(서빙 계층 신설) | 상(둘 다) |
| WYSIWYG↔MD 왕복손실 | 있음(본문만, 관리 가능) | 있음 | 있음 |

### 3.3 추천안 — **(A) GitHub API 커밋 왕복, git 단일 SSOT** ★

**근거**
1. **F1이 절반을 이미 풀었다.** 온오프는 `draft: true` 한 줄 커밋이면 build.py가 알아서 목록·색인·페이지에서 뺀다. 별도 동적 플래그·서빙계층이 필요 없다.
2. **F2가 B/C의 동적 경로를 비싸게 만든다.** 오버레이는 현재 "정적 HTML 직접 서빙" 모델에 글 요청 가로채기 계층을 새로 얹어야 한다 — 과잉설계이고 캐시/성능/이중SSOT 리스크를 부른다.
3. **기존 파이프라인을 그대로 재사용한다.** Actions 빌드·deploy·`/api/update`가 이미 있다. A는 여기에 "원격 커밋" 한 조각만 얹는다. **DB 불필요.**
4. **단일 SSOT = 정합성.** 사이트 표시·sitemap·rss·색인이 모두 build.py 한 곳에서 파생되므로, 편집이 곧 커밋이면 진실이 갈릴 곳이 없다.

**감수하는 것: 즉시성(반영 지연 ~1~3분).** 24편 규모 블로그에서 발행/수정이 초 단위로 급할 이유는 없다. 완화책:
- 저장/토글 직후 UI에 **낙관적 반영 + "반영 대기중(빌드 중)" 배지** 표시.
- 커밋 성공 시 서버가 **Actions를 자동 트리거**(`repository_dispatch` 또는 push 자체가 트리거)하고, 빌드 완료 후 자동으로 `/api/update`를 호출하거나 기존 [프로그램 갱신] 버튼을 그대로 안내.
- "정말 즉시 내려야 하는 긴급 오프"가 실무상 필요해지면 그때 **B-lite(오프만 동적 404)**를 phase-3 옵션으로 검토(현재는 미채택 — 이중SSOT를 만들지 않는다).

### 3.4 frontmatter 규약 (변경 최소화)

| 필드 | build.py가 읽나 | 이번 콘솔이 다루는 방식 |
|---|---|---|
| `title, description, category, slug, funnel, date, author, cover_caption` | 예(`parse()` 화이트리스트) | 편집 폼에서 직접 편집 |
| `draft` | 예 (오프 판정) | **온오프 토글의 대상.** true=비게시 |
| `updated` | 아니오(파일엔 있음) | **저장 시 자동으로 오늘 날짜 세팅** |
| `cluster, tags, thumbnail, faq[]` | `faq`만 부분 파싱, 나머지 미사용 | **편집 시 원문 보존(드롭 금지).** MVP는 읽기전용/원문유지, faq·tags 편집 UI는 phase-2 |

> **핵심 규칙(정합성):** 저장 시 콘솔은 **frontmatter 전체를 파싱→일부 필드만 수정→나머지는 그대로 재직렬화**한다. build.py가 안 읽는 필드(`cluster`, `tags`, `thumbnail`, `faq`)도 절대 잃지 않는다. 새 필드 신설은 하지 않는다(요구된 `status` 대신 기존 `draft`를 쓴다 — F1).

### 3.5 온오프 / 삭제 / 수정의 정확한 동작 정의

- **온오프(게시/비게시)** = `draft` 플래그 커밋.
  - **오프의 의미 = 완전 제거(단순 접근차단 아님).** `draft:true`면 다음 빌드부터 페이지 자체가 생성되지 않아 **404**, 목록·카테고리·홈·sitemap·rss·색인에서 모두 빠진다(build.py:104). 검색엔진에서도 다음 크롤 시 제거됨.
  - 되돌리기: `draft:false`(또는 필드 제거) 커밋 → 다음 빌드에 복귀. 파일·git이력 보존이므로 무손실.
- **삭제(soft, 기본)** = 파일을 `articles/_trash/<file>`로 이동하는 커밋. **가정:** build.py에 `_trash/`와 하위를 스캔 제외하는 1줄(`os.listdir(ART)`는 파일만 보므로 하위폴더는 자동 무시됨 — 실제로 `_trash`를 별도 폴더로 두면 추가 코드 없이 제외된다) → 목록/휴지통에서 복원 가능.
- **삭제(hard)** = `articles/`에서 파일 제거 커밋. 사이트에서 사라지되 **git 히스토리에는 남는다**(진짜 영구소각 아님 — git revert로 복구 가능). 2단계 확인 모달 필수. MVP는 soft만 제공, hard는 phase-3.
- **수정** = 본문(markdown) + 메타(frontmatter 화이트리스트 필드) 편집 → `main`에 커밋. `updated` 자동 갱신. `date`(최초발행)는 유지.

### 3.6 글 상태 전이표 (불가능한 전이까지 명시)

상태: **Published(게시)** · **Draft(비게시)** · **Trash(휴지통)** · **Deleted(하드삭제)** · (표시상태) **Pending(반영대기=커밋됨/빌드전)**

| from \ 액션 | 게시(publish) | 비게시(unpublish) | 휴지통이동(soft del) | 복원(restore) | 하드삭제 | 수정저장 |
|---|---|---|---|---|---|---|
| Published | ✕ 이미 게시(no-op, 멱등) | → Draft | → Trash | ✕ 불가(휴지통 아님) | → Deleted(2단계) | → Pending→Published |
| Draft | → Published | ✕ 이미 비게시(no-op) | → Trash | ✕ 불가 | → Deleted(2단계) | → Pending→Draft |
| Trash | ✕ 불가(먼저 복원) | ✕ 불가 | ✕ 이미 휴지통(no-op) | → Draft(안전기본) | → Deleted(2단계) | ✕ 불가(읽기전용) |
| Deleted | ✕ (git revert만) | ✕ | ✕ | ✕ | ✕ | ✕ |
| Pending(반영대기) | 큐잉/차단 | 큐잉/차단 | 큐잉/차단 | 큐잉/차단 | 큐잉/차단 | 마지막 저장 우선 |

- **멱등:** 이미 게시된 글에 게시 요청 → 200 no-op(커밋 없음). 상태변경 API는 **목표상태 기준 멱등**(F2/at-least-once 대비).
- **Pending 규칙:** 같은 글에 대해 직전 커밋이 아직 빌드 반영 전이면, 새 액션은 최신 sha 기준으로만 허용(3.7 낙관적 동시성). 충돌 시 409.

### 3.7 동시성 · 멱등 (외부연동 at-least-once 가정)
- 모든 쓰기는 GitHub Contents API의 **파일 `sha` 기반 낙관적 잠금**을 쓴다. 조회(get) 시 받은 sha를 저장에 동봉 → 그사이 원격이 바뀌었으면 GitHub가 409 → 콘솔은 "다른 곳에서 이미 수정되었습니다. 새로고침 후 다시 시도" 모달.
- **멱등키:** 클라이언트가 각 쓰기에 `Idempotency-Key`(UUID) 부여. 서버는 최근 처리 키를 `data/idem.log`에 짧게 보관해 동일 키 재요청은 이전 결과를 반환(버튼 연타·재시도 중복 커밋 방지).
- **재시도:** GitHub API 5xx/타임아웃 시 서버가 지수백오프+지터로 최대 2회 재시도. 최종 실패는 사용자에게 사유 노출 + `data/admin.log`에 적재.
- **타임아웃:** GitHub API 호출 10초(가정). 초과 시 실패 처리(부분성공 방지 위해 커밋은 단일 원자적 PUT).

**추가 수집이 필요한 것(이번 비범위, 로드맵 언급):**

**4상태:** 로딩=차트 스켈레톤 / 빈=데이터 없음 문구 / 에러=재시도 / 정상=차트+표.

### 4.3 S-ADM-3-01 글관리 목록

**목록 컬럼:** 체크박스(일괄, phase-2) · 제목 · 카테고리 · 저자 · 발행일(date) · 수정일(updated) · 상태(게시/비게시/휴지통 배지) · 조회수(누적) · 액션.

**필터:** 상태(전체/게시/비게시/휴지통) · 카테고리 · 저자 · 퍼널.
**검색:** 제목/슬러그 부분일치(클라이언트).
**정렬:** 발행일·수정일·조회수·제목. 기본 = 발행일 내림차순.

**행 액션**
| 액션 | 동작 | 확인모달 | API |
|---|---|---|---|
| 수정 | 편집화면 이동 | 없음 | (이동) |
| 온오프 토글 | draft 반전 | 오프 전환 시 (MPU)"이 글을 비게시합니다. 다음 빌드 후 사이트에서 사라집니다(404). 계속?" | `/api/posts/status` |
| 삭제 | 휴지통 이동 | (MPU)"휴지통으로 이동합니다. 복원 가능." | `/api/posts/delete` (mode=soft) |
| 복원(휴지통 행) | Draft로 복원 | 없음 | `/api/posts/restore` |
| 영구삭제(휴지통 행, phase-3) | hard delete | (MPU) 2단계: 슬러그 재입력 | `/api/posts/delete` (mode=hard) |

**행 상태 표시:** 커밋 직후 라이브 반영 전 행은 **"반영 대기중"** 배지 + 액션 일시 비활성.

**4상태**
- 정상: 목록 렌더.
- 로딩: 행 스켈레톤.
- 빈: 필터 결과 0 → "조건에 맞는 글이 없습니다". 전체 0 → "아직 글이 없습니다".
- 에러: `/api/posts` 5xx → "목록을 불러오지 못했습니다 [다시 시도]". 401 → 게이트.
- **권한없음:** (단일 관리자라 해당 적으나) 토큰 만료 시 401→게이트.

**수용 기준(예)**
- Given 15편 게시·3편 비게시, When 상태=비게시 필터, Then 3행만 표시되고 배지가 모두 "비게시".
- Given 어떤 글의 온오프 토글, When 성공, Then 그 행 상태배지가 즉시 반전되고 "반영 대기중" 배지가 붙는다. When `/api/posts/status`가 409, Then 배지는 원복되고 "다른 곳에서 이미 수정됨" 모달이 뜬다.

### 4.4 S-ADM-3-02 글 편집 (WYSIWYG)

**레이아웃:** 상단 메타 폼 + 본문 WYSIWYG + 하단 액션바.

**메타 폼(입력필드 상태 명세)**
| 필드 | 타입 | 검증 | 상태 |
|---|---|---|---|
| title | text (필수) | 공백불가, 200자 이내 | Focus/완료/오류(빈값·초과) |
| description | textarea | 300자 권장(초과 경고) | 완료/오류 |
| category | select(lms/hrd/certification/video/edutech/news) | 필수, 허용값만 | 완료/오류 |
| slug | text | `[a-z0-9-]+`, 중복검사(기존 글과) | 오류(형식/중복) |
| funnel | select(TOFU/MOFU/BOFU) | 선택 | 완료 |

| draft(게시상태) | toggle(게시/비게시) | — | 완료 |
| cluster/tags/thumbnail/faq | (MVP) 읽기전용 원문 보존 표시 | — | Disabled |

**본문 WYSIWYG:** 6장 참조(TOAST UI Editor). **본문만 편집**, frontmatter는 폼이 담당(에디터에 frontmatter를 넣지 않는다 — 오염 방지).

**액션바:** [저장] [저장 후 게시] [취소] [삭제]. 저장 중 버튼 Disabled + 스피너.

**4상태**
- 로딩: `/api/posts/get` 대기 → 폼·에디터 스켈레톤.
- 정상: 값 채워짐.
- 빈(신규작성, phase-2): 빈 폼 + 슬러그 자동생성 힌트.
- 에러: get 404 → "글을 찾을 수 없습니다"(삭제됐을 수 있음) → 목록 복귀. get 401 → 게이트.

**저장 예외 처리**
- 검증 실패 → 해당 필드 오류표시, 저장 차단.
- 409(sha 충돌) → "다른 곳에서 수정됨" 모달 [원격본 보기/덮어쓰기(강제)/취소].
- GitHub API 실패(5xx/타임아웃) → 재시도 안내 + 로컬 draft를 sessionStorage에 임시보관("입력 내용 유지됨").
- 저장 성공 → "반영 대기중" 안내 + 목록 복귀(또는 편집 유지 선택).

**수용 기준(예)**
- Given 본문·제목 편집, When [저장], Then frontmatter 전체가 보존된 채(cluster/tags/faq 포함) title·description·body·updated만 갱신되어 `main`에 1커밋된다.
- Given 저장 중 네트워크 단절, When 실패, Then 입력값이 유지되고 "임시저장됨, 다시 시도" 안내가 뜬다.

## 5. API 명세 (신규 / 변경)

> **Contract-First:** 아래 계약을 d2/d3와 p2가 동시 참조하는 단일 진실원으로 먼저 확정한다. 모든 신규 엔드포인트는 JSP로 `WEB-INF/jsp/` 아래 두고 `web.xml`에 `/api/*` 매핑 추가. 인증은 **Bearer 세션토큰 헤더**(쿼리스트링 비번 금지). GitHub 쓰기는 서버가 보유한 토큰으로 대행.

### 5.1 기존 엔드포인트와의 관계
- **`GET /api/stats`**: 변경 없음(대시보드·통계 페이지가 계속 읽음). 인증만 Bearer로 통일 권장(하위호환 위해 `?pw=`도 당분간 병행 허용 가능 — 가정).
- **`POST /api/update`**: 변경 없음. 커밋 후 "지금 반영" 용도로 재사용. **[확정] 저장 성공 시 자동 호출하지 않고, 사용자가 [프로그램 갱신] 버튼으로 수동 트리거한다.**
- **`POST /api/track`**: 변경 없음.

### 5.2 신규 엔드포인트

**(1) 인증 — `POST /api/auth`**
```
req  : { pw }                         # 본문(쿼리스트링 아님)
res  : 200 { token, expiresIn }       # 불투명 세션토큰
       401 { error:"unauthorized" }
```

**(2) 목록 — `GET /api/posts`**  (Authorization: Bearer)
```
res 200 : { posts:[ {file, slug, title, category, author, funnel,
                     date, updated, draft, status:"published|draft|trash",
                     views } ], generatedAt }
```
- 데이터원: 서버가 **`WEB-INF/posts.json`**(build.py가 생성, 드래프트 포함 전체 메타)을 읽고, `stats` 맵의 `P:/cat/slug/` 조회수를 조인. GitHub API 호출 없음(빠름).
- **가정(build.py 확장):** 빌드 시 드래프트 제외 전(`build.py:99-106`) 전체 목록을 `OUT/WEB-INF/posts.json`으로 덤프. 웹서빙 안 됨(F3).

**(3) 단건 조회 — `GET /api/posts/get?file=<name>`**  (Bearer)
```
res 200 : { file, sha, frontmatter:{...전체...}, body, raw }
       404 { error:"not_found" }
```
- 데이터원: **GitHub Contents API**(`main` 브랜치)로 원문+sha 취득(편집·낙관적잠금용 진실값).

**(4) 저장 — `POST /api/posts/save`**  (Bearer, Idempotency-Key)
```
req : { file, sha, frontmatter:{title,description,category,slug,funnel,author,draft,...preserve...},
        body, message? }
res : 200 { committed:true, newSha, commitUrl }
      409 { error:"sha_conflict" }        # 그사이 원격 변경
      422 { error:"validation", fields:[...] }
      502 { error:"github_unavailable" }  # 재시도 소진
```
- 서버 처리: frontmatter 전체 보존 재직렬화 + `updated=today` → 마크다운 조립 → GitHub Contents API PUT(단일 원자 커밋) to `main`. sha로 낙관적 잠금. Idempotency-Key로 중복 커밋 차단. 5xx는 백오프+지터 2회 재시도, 최종 실패는 502 + `admin.log` 적재(DLQ 성격).

**(5) 상태변경(온오프) — `POST /api/posts/status`**  (Bearer, Idempotency-Key)
```
req : { file, sha, target:"published|draft" }   # 목표상태 기준(멱등)
res : 200 { committed:true|false(noop), newSha }
      409 { error:"sha_conflict" }
```
- `draft` 한 줄만 바꾸는 최소 커밋. 이미 목표상태면 커밋 없이 200 noop(멱등).

**(6) 삭제/복원 — `POST /api/posts/delete` · `POST /api/posts/restore`**  (Bearer, Idempotency-Key)
```
delete  req : { file, sha, mode:"soft"|"hard" }
        soft: articles/<file> → articles/_trash/<file> 이동 커밋
        hard: 파일 삭제 커밋(2단계 확인은 클라이언트가 강제)
restore req : { file, sha }   # _trash/<file> → articles/<file>
res : 200 { committed:true, newSha } / 409 conflict
```

**(7) 이미지 업로드 — `POST /api/posts/image`**  (Bearer) *(phase-3)*
```
req : multipart(file) 또는 { filenameHint, base64 }
res : 200 { url }   # articles/images/<slug>-<n>.<ext> 로 커밋, 상대경로 반환
```
- 주의: build.py가 이미지 인라인(data URI)·`img_map.json`으로 처리(`build.py:21,183-185`)하므로, 업로드 이미지가 실제 페이지에 반영되려면 이미지 매핑 파이프라인 정합이 필요 → phase-3에서 별도 설계.

### 5.3 공통 규약
- 인증 실패 401 / 권한 없음 403 / 검증 422 / 충돌 409 / 상류(GitHub) 장애 502 / 미존재 404.
- 모든 쓰기 응답에 `newSha` 포함(클라이언트가 다음 낙관적 잠금 기준 갱신).

## 7. 보안 · 권한

### 7.1 현재 방식의 한계(쓰기 권한이 붙으면 치명적)
- 비번을 **`?pw=` 쿼리스트링**으로 전달(`stats.jsp:19`, `update.jsp` 호출) → Apache/Resin **액세스로그·Referer에 평문 잔존**. 읽기전용일 땐 감내했으나, 이제 **커밋·삭제·git실행**이 붙으므로 유출 시 콘텐츠 변조 가능.
- 단일 공유 비번, 세션 개념 없음(매 요청 비번 재전송).
- **가정:** GitHub 토큰이 새로 도입되므로 비번보다 더 강한 비밀 관리가 필요.

### 7.2 최소 보강안 (MVP 필수)
1. **쿼리스트링 비번 폐지 → `POST /api/auth`로 세션토큰 발급, 이후 `Authorization: Bearer`.** (F4 정면 해소)
2. **GitHub 토큰 분리 보관:** fine-grained PAT(대상 저장소 `contents:write`만)를 **`/home/blog/data/github.token`**(git 밖·웹서빙 밖·`reset --hard` 생존)에 두고 JSP만 읽음. 브라우저에 절대 노출 금지.
3. **파괴적 작업 재인증:** 삭제(특히 hard)·상태일괄변경 전 비번/토큰 재확인.
4. **감사 로그:** `data/admin.log`에 모든 쓰기 append(누가=단일관리자, 언제, 무엇, sha, 결과).
5. **로그인 시도 제한:** 실패 N회 시 지연/차단(상수시간 비교는 이미 있음 `stats-store.jspf:117`).
6. **noindex·robots 비노출 유지**(현행 그대로, `build.py:379-381`).
7. **HTTPS 강제** 전제(관리 트래픽).

### 7.3 인가(RBAC) — 인증과 분리, 미래 확장만 정의
- **원칙(교훈):** 인증("누구인가")과 인가("무엇을 할 수 있나")를 분리. MVP는 단일 사용자·단일 역할이지만 **행위 묶음(Scope)** 으로 정의해 두면 확장 시 코드 흔들림이 없다.

| Role | Scope(행위) | MVP |
|---|---|---|
| viewer | stats:read, posts:read | (미사용) |
| editor | + posts:write(save) | (미사용) |
| publisher | + posts:status, posts:delete(soft) | (미사용) |
| admin | + posts:delete(hard), system:update | **현재 유일 역할** |

MVP는 `admin` 하나만 구현하되, API는 스코프 상수로 게이팅해 phase-3에서 역할 추가가 데이터 변경만으로 되게 한다.
